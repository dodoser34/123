# K-Beauty | C-Health — интернет-магазин корейской косметики и трав (фронтенд)

Чистые **HTML, CSS и JavaScript** без фреймворков и сборки.
Подробная документация для нетехнических читателей лежит в `../docs/` (начните с `00-Оглавление.md`).

## Запуск

Откройте `index.html` в браузере. Удобнее через локальный сервер:

```bash
python deploy/serve_frontend.py
```

После этого откройте http://localhost:5174

## Вход и регистрация

**Вход нужен только для покупки.** Все страницы открыты гостям, кроме оформления заказа (`checkout`), личного кабинета (`account`) и админки (`admin`): с них `js/core/auth-guard.js` (подключается сразу после `store/*.js`, до отрисовки) отправляет гостя на `pages/login.html?next=<страница>`. Отзыв гость тоже оставляет после входа. После входа или регистрации посетитель возвращается на страницу из `next` (по умолчанию — на главную, администратор — в админку). При выходе из аккаунта на закрытой странице она сразу закрывается.

На `pages/login.html` вкладки «Вход» и «Регистрация» переключаются без перезагрузки, с анимацией (`js/pages/login.js`). Регистрация создаёт покупателя. Email не должен повторяться; пароль — не менее 8 символов, с подтверждением.

Под формой входа — «Быстрый вход для проверки» (`demo/data/accounts.js`). Демо подключается только на `localhost`/`127.0.0.1`, `file://` и `*.github.io` (`DEMO_HOST` в `js/app.js`), и только без сервера:

- покупатель — `buyer@demo.kz` / `demo123`;
- администратор — `admin@demo.kz` / `admin123`.

Это статичная демонстрация для GitHub Pages: аккаунты и заказы сохраняются в localStorage текущего браузера. Серверной авторизации и синхронизации между устройствами нет.

## Демо-наполнение (`demo/`)

Товары, отзывы, демо-аккаунты, демо-заказы и фото демо-товаров лежат только в `demo/` (`demo/data/*.js`, `demo/images/products/`). Загрузчик подключает их из списка `DEMO` в `js/app.js`.

Запуск без демо: удалите `demo/`, впишите email владельца в `App.config.adminEmails` и зарегистрируйтесь с ним — роль `admin` выдаётся автоматически. `store/seed.js` запоминает id демо-записей (`kbch.v1.demo-ids`) и при отсутствии `demo/` удаляет их из localStorage, не трогая остальные данные. Чтобы не было 404 на `demo/data/*.js`, очистите массив `DEMO`.

## Переходы

`components/transitions.js` + `css/components/transitions.css`: cross-document View Transitions (`@view-transition`), morph фото товара `product-photo` (карточка ↔ `.pp-main img`), `ui.transition(update, type)` для same-document обновлений (каталог, корзина, избранное, вкладки ЛК, разделы админки), `ui.nameCards`, `ui.tabsInk`, `ui.slideIn`, `ui.flyToCart`. Скрипты подключаются с `blocking="render"`, чтобы первый кадр уже был отрисован.

## Оплата

Демо-режим (`pages/checkout-payment.js`): карта (проверка Луна, срок, CVC; сохраняются только последние 4 цифры, тестовый номер `4242 4242 4242 4242`) или наличные при получении. Реального списания нет.

Для размещения укажите папку `frontend/` как публикуемый артефакт GitHub Pages. Пути к стилям, скриптам и изображениям относительные и работают под адресом репозитория.

## Структура

```
frontend/
├─ index.html, 404.html    главная и 404 — в корне (так требует GitHub Pages)
├─ pages/*.html            остальные страницы: catalog, product, about, delivery, cart, checkout, favorites, login, account
├─ admin/index.html        админ-панель
├─ texts/ru/*.js           ВСЕ ТЕКСТЫ САЙТА по разделам (common, home, catalog, product…); инструкция — texts/README.md
├─ demo/                   демо-наполнение: data/*.js + images/products/ (удаляется целиком)
├─ css/
│  ├─ main.css             подключает все стили магазина по порядку
│  ├─ admin.css            стили магазина + admin/*
│  ├─ base/                variables.css (палитра, шрифты), base.css (сброс, типографика, сетка), interaction.css
│  ├─ components/          кнопки, шапка, мобильное меню, карточка товара, формы, модальные окна, анимации…
│  ├─ pages/               стили конкретных страниц
│  ├─ responsive/          ВСЯ АДАПТАЦИЯ: index.css (порядок), desktop/ (laptop, 2K–8K), tablet/ и phone/ (по разделам),
│  │                       phone/landscape, touch/ (сенсорные экраны), accessibility/, admin/
│  └─ admin/               каркас, таблицы, форма товара…
├─ js/
│  ├─ app.js               загрузчик: одна строка в <head> подключает всё по списку
│  ├─ config.js            настройки магазина (название, WhatsApp, email, адрес, соцсети, доставка)
│  ├─ core/                utils (в т.ч. ui.page — адреса страниц), icons, texts (ui.t), auth-guard, start
│  ├─ data/                стартовые категории
│  ├─ store/               «склад» App.db: storage, products, categories, users, session, cart, favorites, orders, reviews,
│  │                       migrations (обновления формата данных), seed (первое заполнение)
│  ├─ components/          шапка, подвал, мобильное меню, карточка товара, уведомления, окна, карусель…
│  ├─ pages/               логика страниц; крупные страницы разбиты на части:
│  │                       catalog-{state,filters,toolbar,results}, product-{seo,gallery,info,reviews,review-form},
│  │                       account-views, checkout-payment
│  └─ admin/               админка: каркас + по файлу на раздел
└─ assets/images/
   ├─ products/            фото настоящих товаров (по разделам; доп. ракурсы: имя-2.jpg, имя-3.jpg)
   ├─ pages/               home/, about/ (в т.ч. gallery-1…6), delivery/, login/
   ├─ common/              empty-state.png, og-image.jpg
   └─ decor/               веточки-украшения (PNG)
```

Принципы:

- «один файл — одна задача»; страница, которая разрастается, делится на части `<страница>-<часть>.js`, каждая часть публикует свой объект в `App` (например, `App.catalogState`), а главный файл страницы только связывает их;
- никаких `style="…"` в HTML — всё оформление в `css/`;
- стили в CSS указывают на картинки относительно своего файла: из `css/pages/*.css` это `../../assets/images/…`.

## Тексты и языки

Ни одна надпись не зашита в HTML или JS: в HTML стоят метки `data-t="about.title"` (и `data-t-placeholder`, `data-t-label`, `data-t-alt`, `data-t-title`),
в скриптах — `ui.t('catalog.found', { count })`. Подстановки: `{count}`, форма слова — `{count|товар|товара|товаров}`.
Заголовок вкладки и meta description — из `<раздел>.meta`. Язык берётся из `<html lang>` → `texts/<lang>/`.
Новый текст = новый ключ в нужном файле `texts/ru/*.js`. Админка пока использует свои тексты в `js/admin/` (кроме статусов заказов и общих справочников).

## Адреса страниц

Все ссылки в скриптах строятся через `ui.page('catalog', { cat: 'herbs' })` (учитывает, из какой папки открыта страница).
`'home'` — главная, `'admin'` — админка, остальные имена — файлы в `pages/`.

## Как подключаются скрипты

В каждой странице — одна строка:

```html
<script src="../js/app.js" data-page="catalog"></script>  <!-- для pages/*.html -->
```

`app.js` по `data-page` подгружает общие файлы и скрипт страницы (обычные `<script>` с `async=false`, порядок сохраняется). Поэтому сайт работает и с локального сервера, и просто при открытии файла с диска. Список файлов для каждой страницы задан в объекте `PAGES` внутри `app.js`.

## Версия кеша

Во всех местах стоит одно число (сейчас `20`). При выкладке изменений поднимите его везде сразу: `VERSION` в `js/app.js`, `?v=` у `app.js` и CSS в каждом HTML, `@import ...?v=` в `css/main.css` и `css/admin.css`.

## Данные и миграции

Ключи localStorage — `kbch.v1.*`. `store/seed.js` хранит `VERSION` данных, `store/migrations.js` по шагам дописывает новые поля товаров, отзывы и пути к фото в уже сохранённые данные, не затирая правки из админки. Меняете формат данных — добавьте шаг в `migrations.js` и поднимите `VERSION` в `seed.js`.

## Форматирование

```bash
npx prettier@3.3.3 --write "frontend/**/*.{html,css,js}"
```

Настройки — в `.prettierrc.json` и `.editorconfig` в корне репозитория (ширина строки 140, одинарные кавычки, LF).

## Что заполнить заказчику

- `js/config.js`: номер WhatsApp, email, ссылки на соцсети, порог бесплатной доставки. Адрес **намеренно пустой** — пока он пустой, сайт нигде не показывает адрес и карту.
- `texts/ru/*.js`: все тексты сайта; `texts/ru/delivery.js` — сроки, стоимость доставки, ответы в FAQ.

## Важно: это фронтенд-демо

Данные хранятся в `localStorage` каждого браузера (префикс ключей `kbch.v1.`). Для реального магазина:

1. Перепишите файлы `js/store/*.js` на запросы к API. Интерфейс `App.db` остаётся прежним, страницы менять не нужно.
2. Авторизацию, регистрацию, роли и хранение паролей перенесите на сервер; удалите демо-аккаунты и демо-заказы.
3. Загрузку фото из админки переведите на сервер или в облачное хранилище. Сейчас фото хранятся в base64 в браузере, всего около 5 МБ.
4. Для продакшена файлы можно склеить и сжать любым сборщиком. Структура папок это позволяет.
