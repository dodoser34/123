# Отдельная экосистема демонстрации

Вся демонстрация GitHub Pages находится в этой папке. Основной магазин остаётся в `frontend/`, сервер — в `backend/`.

| Путь | Содержимое |
| --- | --- |
| `data/` | 21 товар, отзывы, тестовые аккаунты и заказы |
| `images/products/` | Все 65 фото товаров и дополнительные ракурсы |
| `runtime/` | Заполнение, миграции демо, быстрый вход и имитация оплаты |
| `css/` | Оформление демо-блоков |
| `config.json` | Подключаемые модули и отдельное хранилище браузера |
| `build.py` | Сборка демонстрации, проверка каждого пути к фото |
| `serve.py` | Локальный запуск демонстрации |
| `github-pages/action.yml` | Подготовка и публикация демонстрации на GitHub Pages |
| `tests/` | Проверки сборки, фото и удаления экосистемы |
| `seed_backend.py` | Необязательный ручной импорт примеров в локальную БД; production запрещён |
| `.public/` | Собранная демо-копия; создаётся автоматически, не хранится в Git |

## Запуск

Из корня проекта:

```powershell
python demo/serve.py
```

Откройте `http://localhost:5175`. Для порта 5174: `python demo/serve.py 5174` (порт должен быть свободен).

Демо-аккаунты: покупатель `buyer@demo.kz` / `demo123`, администратор `admin@demo.kz` / `admin123`.
Демонстрация работает в отдельном хранилище `kbch.demo.v1.*`, без API и реальных платежей. Вводите только тестовые реквизиты карты.
Вход по коду и восстановление пароля имитируются тестовым кодом `246810`; письма не отправляются. Кнопка Google показывает пояснение: настоящий OAuth доступен в основном сайте при настроенном API и ключах Google.

Сборка без запуска: `python demo/build.py`. Тесты: `python -m pytest demo/tests -q`.
Сборка останавливается, если отсутствует хотя бы одно фото товара. Все изображения копируются в `demo/.public/demo/images/`.

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускает `demo/github-pages/action.yml`. GitHub обнаруживает workflow исключительно в `.github/workflows`; поэтому небольшой файл запуска остаётся за пределами папки.
Публикуется только `demo/.public/`. Переменная репозитория `API_URL` на демонстрацию не влияет: подключение к рабочему API исключено из её конфигурации.

## Удаление в два действия

1. Удалите корневую папку **`demo/` целиком**.
2. Удалите **`.github/workflows/pages.yml`**.

Основной магазин, API, production-сборка `deploy/prepare_frontend.py` и серверные тесты работают без этих файлов. Если удалить только папку, оставшийся workflow пропустит публикацию без ошибки.
В `frontend/` нет демо-данных, демо-фото или обязательных импортов из этой папки. Production-сборка не копирует её.

Уже опубликованная версия GitHub Pages остаётся на стороне GitHub до отключения через Settings → Pages → Unpublish site. Исходники её не удаляют автоматически. Ранее вручную импортированные примеры в существующей локальной БД также сохраняются; удаление папки не стирает базы.
