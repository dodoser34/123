# 18. Подготовка запуска примерно за час

Этот план рассчитан на VPS с Ubuntu и один домен для сайта, `/api` и `/media`. Он не запускает магазин сам. Если DNS, доступ к серверу или отправка писем ещё не готовы, час отсчитывается после их подготовки. Регистрация домена, ожидание DNS, разрешение SMTP у хостера и согласование Google OAuth могут занять больше времени.

## Подготовить заранее

- Доступ по SSH к VPS, открытые TCP 80/443, Docker Engine с Compose v2, Git, Python 3.11+, свободный диск; ориентир памяти — 2 ГБ. Входящий порт PostgreSQL открывать не нужно.
- Домен и `www` направлены на VPS. Лишние/старые AAAA-записи удалены или исправлены. HTTPS выпускается для обоих имён; убедитесь, что порт 80 пока свободен.
- Настоящие почта администратора и уникальный пароль, случайные `SECRET_KEY` и пароль PostgreSQL, SMTP с рабочей отправкой писем. Заполняются только на сервере в `deploy/.env`; значения не присылайте в чат и не коммитьте.
- Реальные реквизиты Kaspi либо `PAYMENT_METHODS=cash`, реальные цены, остатки, категории, товары и фото. Демо из `demo/` и браузерные данные GitHub Pages автоматически в PostgreSQL не переносятся. Подготовка полного каталога — отдельная работа.
- Google OAuth необязателен: без Client ID/secret кнопка скрыта. Для него заранее нужен web-клиент и redirect URI `https://<домен>/api/auth/google/callback`; подтверждение кабинета Google не входит в час.
- Место для внешних копий базы и фото, а также человек, который проверит настоящее письмо и тестовый заказ.

## 0–15 минут: код, настройки и проверка перед запуском

Команды выполняются из корня клонированного репозитория. Полная инструкция настройки — [раздел 11](11-Бэкенд-и-деплой.md).

```bash
umask 077
cp deploy/.env.example deploy/.env
nano deploy/.env
python3 deploy/prepare_frontend.py
docker compose --env-file deploy/.env -f deploy/docker-compose.yml config --quiet
docker compose --env-file deploy/.env -f deploy/docker-compose.yml build backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps backend python -m app.cli check
```

Исправьте все ошибки проверки перед следующим шагом. `config --quiet` проверяет конфигурацию без печати секретов; обычный `config` может вывести их. Не публикуйте `.env`, полный вывод `docker inspect` и дампы базы. Зафиксируйте выбранный коммит: `git rev-parse HEAD`.

## 15–30 минут: HTTPS и запуск

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml --profile init run --rm --service-ports certbot-init
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec web nginx -t
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec backend python -m app.cli seed --frontend /frontend
```

При обычном запуске API проверяет настройки и возможность записи фото, выполняет `alembic upgrade head` и только затем запускает сервер. `seed` добавляет категории, не товары. В первый запуск Nginx может быть готов раньше миграций — дождитесь здорового `backend` в `ps`. Если API перезапускается, проверьте `logs --tail=100 backend` и исправьте причину; пустая главная страница не означает успешный запуск магазина.

## 30–50 минут: проверка настоящего магазина

Проверяйте домен VPS в приватном окне браузера. GitHub Pages остаётся отдельной демонстрацией.

1. HTTP переходит на HTTPS, `www` — на основной домен; нет ошибки сертификата. `/api/health` возвращает `{"status":"ok"}`. `/api/categories` и `/api/products` отвечают без ошибок.
2. Администратор входит. Через админку создайте реальный товар с фото, ценой и остатком; добавьте ещё фото, измените цену/остаток, скройте и верните видимость. Откройте каталог с телефона и компьютера. После перезапуска API фото и товар должны остаться.
3. На отдельной почте покупателя получите настоящее письмо, подтвердите почту, войдите и выйдите, запросите восстановление пароля. Если подключён Google, проверьте вход из приватного окна и возврат на нужный домен.
4. Добавьте товар в корзину, увеличьте и уменьшите количество, удалите и добавьте снова. Проверьте доставку и сумму, оформите один тестовый заказ без реального платежа. Администратор видит его, покупатель — только свой. Изменение статуса видно покупателю; товар с нулевым остатком не оформляется.
5. Вне аккаунта `/api/admin/users` должен отказать в доступе, а `/.env`, `/backend/.env` и `/.git/config` не должны отдавать содержимое. В админке → Настройки → «Готовность к запуску» нет обязательных недостающих настроек.

До этого момента не направляйте реальных покупателей на сайт. Если письма или заказ не работают, запуск ещё не готов; временное отключение ошибки не заменяет проверку.

## 50–60 минут: сохранность и передача

Сначала убедитесь, что автоматическая копия появилась: `docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs --tail=20 backup` и `ls -lh deploy/backups/`. У каждой даты должны быть `.dump` и `media-…tgz`.

Перед важным обновлением снимите согласованную ручную пару с короткой остановкой API:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T backup sh -c 'umask 077; pg_dump -Fc -f /backups/kbch-before-update.dump && tar czf /backups/media-before-update.tgz -C /media . && pg_restore --list /backups/kbch-before-update.dump >/dev/null && tar tzf /backups/media-before-update.tgz >/dev/null'
docker compose --env-file deploy/.env -f deploy/docker-compose.yml start backend
```

Не перезаписывайте эту пару при следующем обновлении: переименуйте её с датой. Скопируйте её за пределы VPS. Проверка списка архива не заменяет пробное восстановление: на отдельной базе/томе восстановите копии и убедитесь, что выбранные товар, фото и тестовый заказ открываются. Боевой том для проверки не очищайте. Полный запуск Docker/PostgreSQL/Nginx, выпуск сертификата, SMTP и восстановление требуют целевой машины — локальные тесты кода этого не подтверждают.

Сохраните адрес сайта, коммит, дату успешной проверки, местоположение внешних копий и доступы в менеджере паролей. Демо-товары и тестовый заказ удаляйте осознанно через админку.

## Откат после неудачного обновления

До обновления запишите рабочий коммит и создайте указанную пару. Если миграций схемы не было, верните этот коммит, повторите `python3 deploy/prepare_frontend.py` и `docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build`. Проверьте HTTPS, товар, фото и вход.

Если новая версия уже изменила схему, одного старого коммита недостаточно. Остановите API, сохраните текущую базу отдельно, верните рабочий код и восстановите **выбранную** копию базы:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop backend
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T backup sh -c 'pg_restore --exit-on-error --clean --if-exists -d "$PGDATABASE" /backups/kbch-before-update.dump'
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps --user root --entrypoint sh -v "$PWD/deploy/backups:/restore:ro" backend -c 'tar xzf /restore/media-before-update.tgz -C /app/media && chown -R app:app /app/media'
python3 deploy/prepare_frontend.py
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
```

Фото из архива дополняют/перезаписывают файлы тома, лишние файлы автоматически не удаляются. Восстановление базы заменяет данные: заказы после даты копии будут потеряны, поэтому выбор копии и остановку магазина нужно согласовать с владельцем. Не используйте `down -v`: это удаляет постоянные тома. Для первой публикации без предыдущей версии при провале проверок оставьте магазин закрытым до исправления.

## Если выбран Render

Используйте [вариант 2 раздела 11](11-Бэкенд-и-деплой.md#вариант-2-render-без-своего-сервера): подтвердите стоимость платных API/PostgreSQL/диска, заполните адреса и секреты, запустите Blueprint и выполните ту же проверку письма, заказа и сохранности фото. Команды Docker Compose выше относятся только к VPS. Категории и реальные товары на Render заполняются через админку. Откат схемы и копий выполняется средствами PostgreSQL/Render, предварительно проверенными на отдельной базе. Бесплатный API без постоянного диска для боевых фото не подходит.
