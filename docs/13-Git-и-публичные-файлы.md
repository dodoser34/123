# Что попадает в GitHub и в деплой

Корневой `.gitignore` действует во всех вложенных папках. В `backend/`, `deploy/` и папке фронтенда есть дополнительные правила для локальных файлов этих частей проекта.

В Git остаются исходники, документация, миграции базы, тесты, настройки сборки и шаблоны `.env.example`, `.env.sample`, `.env.template`. Шаблоны должны содержать только примеры, без настоящих паролей и ключей.

В Git не попадают:

- `.env` и его рабочие варианты, приватные ключи, файлы учётных данных;
- виртуальные окружения, зависимости, кеши и результаты проверок;
- локальные базы, логи, письма с кодами, резервные копии и экспорт данных покупателей;
- загруженные на сервер файлы из `backend/media/`, локальные Docker-тома и HTTPS-ключи;
- настройки редакторов и AI-инструментов, временные файлы и проверочная галерея декора.

Личные документы и выгрузки храните в папках `private/`, `.private/`, `personal/`, `exports/` или `backups/`: эти имена исключаются на любой глубине. Публичные фото сайта хранятся в `frontend/assets/`; это предназначенные для публикации материалы.

## Папка для публикации

Из корня проекта выполните:

```bash
python3 deploy/prepare_frontend.py
```

На Windows можно использовать `python` вместо `python3`. Скрипт берёт файлы из `frontend/` и создаёт `.public/`. Он копирует только страницы, JS/CSS, тексты, демо-данные, изображения и шрифты. Документация, проверочные HTML-страницы в папке изображений, скрытые файлы, личные папки и резервные копии исключаются.

`.public/` и `.public-build.json` — служебные результаты сборки. Не храните там личные файлы: повторный запуск заменяет ранее созданную сборку. Чужую или вручную созданную непустую папку `.public/` скрипт не заменяет.

Для подстановки публичного адреса API из переменной окружения используйте:

```bash
python3 deploy/prepare_frontend.py --api-url-from-env API_URL
```

В `env.js` попадает только адрес API. Пароли, SMTP-ключи, OAuth-секреты и реквизиты из `deploy/.env` остаются на сервере. Адрес API с логином/паролем или параметрами запроса скрипт отклоняет.

GitHub Pages и Render готовят `.public/` автоматически. Перед запуском или обновлением VPS нужно запустить подготовку вручную: Nginx и контейнер начального наполнения читают `.public/`, а не всю исходную папку фронтенда. [Настройка публикуемой папки на Render](https://render.com/docs/blueprint-spec).

## Проверка правил Git

```bash
git check-ignore -v deploy/.env backend/.env backend/dev.db backend/.venv/ private/client-notes.txt
git ls-files -ci --exclude-standard
```

Вторая команда должна ничего не вывести: игнорируемые файлы не должны оставаться в индексе. Добавление правила не исключает ранее отслеживаемый файл автоматически. Для такого файла используйте `git rm --cached -- путь/к/файлу`: он останется на диске.

Эти правила защищают будущие добавления. Если настоящий секрет уже был опубликован, удаление из текущего индекса не убирает его из истории: ключ или пароль нужно заменить отдельно.
