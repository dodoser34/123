# 15. Безопасность

Что защищено, где это сделано и как проверяется. Каждая защита покрыта тестом в `backend/tests/test_security.py` (запуск: `python -m pytest` в папке `backend`; в GitHub тесты идут автоматически — на SQLite и на PostgreSQL).

## Кратко

| Угроза | Защита | Где в коде |
|---|---|---|
| **SQL-инъекции** | Все запросы к базе — через SQLAlchemy с параметрами, строки из запроса никогда не склеиваются в SQL. Входные данные проверяются схемами (длина, формат, допустимые символы) | `backend/app/db/`, `backend/app/schemas/` |
| **XSS** (чужой скрипт на странице) | Сервер очищает HTML в текстах сайта (остаются только `<b> <i> <br> <small>` без атрибутов) и запрещает ссылки `javascript:` / `data:` в фото. Сайт выводит данные экранированными и повторно чистит правки текстов. Политика CSP запрещает встроенные и чужие скрипты | `backend/app/core/sanitize.py`, `frontend/js/core/texts.js`, CSP в каждом HTML и в Nginx |
| **Перебор паролей и кодов** | Лимиты попыток на IP и на почту, не больше 5 попыток ввода кода, коды живут 10 минут, пауза между письмами | `backend/app/core/rate_limit.py`, `backend/app/api/routers/auth.py` |
| **DDoS / флуд** | Nginx: лимит запросов и соединений с IP, таймауты медленных клиентов. API: общий лимит запросов с IP, лимит размера запроса (1 МБ, фото — 8 МБ), таймаут запросов к базе | `deploy/nginx/security.conf`, `backend/app/core/middleware.py` |
| **Кража базы** | Пароли — только bcrypt-хеш, токены входа — только SHA-256, коды из писем — HMAC. Из украденной базы нельзя войти ни в один аккаунт | `backend/app/core/security.py` |
| **Доступ к базе** | PostgreSQL во внутренней сети Docker без выхода наружу, отдельный пароль, ограничения CHECK (цены ≥ 0, оценка 1–5, только известные роли и статусы), ежедневные резервные копии | `deploy/docker-compose.yml`, `backend/app/db/models.py`, миграции |
| **Чужие права** | Каждый маршрут админки проверяет роль; роль нельзя передать в запросе; администратор задаётся только в `deploy/.env` | `backend/app/api/deps.py` |
| **CSRF** | Вход по токену в заголовке `Authorization`, cookie не используются; CORS разрешает только адрес сайта | `backend/app/main.py` |
| **Clickjacking** | `X-Frame-Options: DENY`, `frame-ancestors 'none'` | Nginx, middleware |
| **Подмена цены** | Сумму считает сервер по ценам из базы, наличие проверяется с блокировкой строки | `backend/app/api/routers/orders.py` |
| **Вредный файл под видом фото** | Тип файла проверяется по содержимому (сигнатуре JPG/PNG/WEBP), имя придумывает сервер | `backend/app/api/routers/catalog.py` |
| **Поддельное уведомление об оплате** | Подпись HMAC, сверка суммы, повторы игнорируются | `backend/app/services/payments/kaspi_pay.py` |
| **Утечка секретов** | Секреты — только в `deploy/.env` (в `.gitignore`), в настройках хранятся как `SecretStr` (не печатаются в журналах), в ответы API не попадают; ошибки сервера отдаются без подробностей | `backend/app/core/config.py`, `backend/app/core/middleware.py` |
| **Небезопасный запуск** | В рабочем режиме сервер не стартует со слабым `SECRET_KEY`, коротким паролем администратора, без PostgreSQL, без почты, с `CORS=*`; документация API выключена | `Settings.problems()` в `backend/app/core/config.py` |
| **Подмена IP** | IP посетителя берётся из заголовка, который ставит наш Nginx, а не из присланного посетителем | `client_ip()` в `backend/app/core/rate_limit.py` |
| **Служебные файлы** | Сайт публикуется из `.public/` — только страницы, стили, скрипты и картинки; Nginx не отдаёт `.env`, `.git`, `*.md`, `*.py`, резервные копии | `deploy/prepare_frontend.py`, `deploy/nginx/default.conf.template` |

## Учётная запись администратора

- Почта и пароль — **только** в `deploy/.env` на сервере (или в панели Render). В git, в коде и в ответах API их нет.
- Надёжнее хранить не пароль, а его хеш: `python -m app.cli hash-password` → `ADMIN_PASSWORD_HASH`.
- При каждом запуске сервер приводит аккаунт администратора в соответствие с `.env`: сменили пароль в файле — после перезапуска действует новый. Роль администратора у других аккаунтов снимается.
- Администратора нельзя удалить или заблокировать через сайт.

## Заголовки безопасности

| Заголовок | Значение |
|---|---|
| `Content-Security-Policy` | Сайт: скрипты только свои, шрифты — Google Fonts, без встраивания в чужие страницы. API: `default-src 'none'` |
| `Strict-Transport-Security` | только HTTPS, 1 год |
| `X-Content-Type-Options` | `nosniff` — браузер не «угадывает» тип файла |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | адрес страницы не передаётся чужим сайтам |
| `Permissions-Policy` | камера, микрофон, геолокация отключены |
| `Cache-Control: no-store` | ответы API (токены, личные данные) не кешируются |

> Если меняете встроенный скрипт в `frontend/404.html`, пересчитайте его хеш в CSP (в `404.html` и `deploy/nginx/headers.conf`) — иначе браузер его заблокирует.

## Ограничения частоты запросов (по умолчанию)

| Что | Лимит | Настройка в `deploy/.env` |
|---|---|---|
| Вход с одного IP | 10 в минуту | `RATE_LOGIN` |
| Попытки входа в один аккаунт | 5 в минуту | `RATE_LOGIN_EMAIL` |
| Письма с кодами | 5 в минуту (и не чаще раза в минуту на почту) | `RATE_CODES`, `CODE_RESEND_SECONDS` |
| Регистрации с одного IP | 5 в час | `RATE_REGISTER` |
| Заказы, отзывы, голоса, загрузки | 60 в минуту | `RATE_WRITE` |
| Все запросы к API с одного IP | 300 в минуту | `RATE_GLOBAL` |
| Nginx: страницы / API / вход | 30 / 10 в секунду / 10 в минуту | `deploy/nginx/security.conf` |

Превышение — ответ «Слишком много попыток» (код 429) с временем ожидания.

## Чек-лист перед запуском

- [ ] `deploy/.env` заполнен, `python -m app.cli check` — без ✗
- [ ] `SECRET_KEY` и `POSTGRES_PASSWORD` — случайные, нигде больше не используются
- [ ] пароль администратора ≥ 12 символов (лучше — `ADMIN_PASSWORD_HASH`)
- [ ] письма приходят (зарегистрируйте тестовый аккаунт)
- [ ] сайт открывается по `https://`, `http://` перенаправляет на `https://`
- [ ] в `deploy/backups/` появилась первая копия базы (через минуту после запуска)
- [ ] на сервере открыты только порты 22, 80, 443 (`ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable`), вход по SSH — по ключу
- [ ] копии `deploy/backups/` регулярно забираются на другой компьютер
