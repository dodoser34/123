# 8. Как это было сделано

## Путь от идеи до сайта

```
 1. Общий макет-коллаж ──► 2. Подробные ТЗ на каждую страницу ──► 3. Отдельные макеты (references/)
                                                                         │
 6. Документация ◄── 5. Проверка на всех экранах ◄── 4. Вёрстка и программирование (site/)
                                                                         │
                                         Задание на фото для нейросети (prompts/IMAGES.md)
```

1. **Исходный макет** — одна картинка-коллаж со всеми страницами: главная, каталог, товар, о нас, доставка, мобильное меню.
2. **Техническое задание (ТЗ).** По коллажу были написаны подробные описания каждой страницы: цвета, шрифты, размеры, тексты, поведение кнопок.
3. **Макеты страниц.** По ТЗ нейросеть сгенерировала отдельные подробные макеты (`references/`). По ним шла вёрстка.
4. **Вёрстка и программирование.** Сначала дизайн-система (цвета, шрифты, кнопки, карточки), потом общие детали (шапка, подвал, карточка товара), потом страницы по очереди, в конце — админка.
5. **Проверка.** Каждая страница открывалась в браузере. Проверялись ошибки, весь путь покупателя (корзина → вход под демо-аккаунтом → заказ → кабинет) и путь администратора (создать, изменить, удалить товар, загрузить фото, сменить статус заказа), а также все размеры экранов.
6. **Документация** — то, что вы читаете.

## Ключевые решения и почему они такие

| Решение | Почему |
|---|---|
| **Только HTML, CSS и JS, без фреймворков** | Так попросил заказчик. Плюсы: не нужна сборка, сайт открывается двойным щелчком, его поймёт любой веб-разработчик, его можно разместить на любом дешёвом хостинге |
| **Данные в памяти браузера (localStorage)** | Задача этапа — только фронтенд. Так сайт полностью «живой» уже сейчас, без сервера |
| **Весь доступ к данным через «склад» (`assets/js/store/`)** | Чтобы при подключении сервера переписать один файл, а не весь сайт |
| **Шапка, подвал и карточка товара — общие компоненты (`assets/js/components/`)** | Одно изменение сразу применяется на всех страницах |
| **Код разложен по папкам: «один файл — одна задача»** | Файлы маленькие (15–200 строк) с понятными названиями: нужное место легко найти, правка не задевает остальное |
| **Один загрузчик `app.js` на странице** | В HTML одна строка вместо 30; список файлов и их порядок — в одном месте |
| **Регистрация + быстрый вход в демо-аккаунты** | Покупатель может создать аккаунт, а заказчик и тестировщики попадают в нужную роль в один клик |
| **Демо-оплата вместо настоящей** | Настоящая оплата делается только через сервер. Демо-форма показывает весь путь покупателя и не хранит номер карты |
| **Подробная карточка товара: «для чего», «кому», теги, состав, применение** | Покупателю проще выбрать, а метки сразу работают как фильтры каталога и поиск |
| **Рейтинг считается только по опубликованным отзывам** | Цифры на карточке всегда совпадают с тем, что покупатель видит во вкладке «Отзывы» |
| **Код отформатирован единообразно (Prettier)** | Все файлы оформлены по одним правилам: отступы, кавычки, переносы. Читать и сравнивать версии проще |
| **Название «K-Beauty \| C-Health» хранится в одном месте (`config.js`)** | Шапка, подвал и админка берут название оттуда |
| **Один шаблон `product.html` для всех товаров** | Новый товар из админки автоматически получает страницу |
| **Фильтры каталога в адресе страницы** | Ссылкой на подборку можно поделиться; работает кнопка «Назад» |
| **Заглушки вместо отсутствующих фото** | Сайт выглядит аккуратно ещё до фотосессии; фото подставятся сами |
| **Цвета через переменные** (`--primary` и т.д.) | Фирменный цвет меняется в одном месте для всего сайта |
| **Фото в админке уменьшаются автоматически** | Память браузера маленькая (~5 МБ), а фото с телефона весят 3–10 МБ |
| **Масштабирование `zoom` на 2K/4K** | Дизайн остаётся пропорциональным и читаемым на огромных мониторах |
| **Фото растворяются в фоне через маску, а не через цветную накладку** | Нет «швов» и полос на краях фото на любом экране |
| **Номер версии в адресах файлов (`?v=10`)** | После обновления сайта браузеры посетителей сразу берут новые файлы, а не старые из памяти |
| **Адрес скрывается, если не заполнен** | По просьбе заказчика адрес пока не публикуется; появится автоматически, когда его впишут |

## Дизайн-система
- **Палитра:** кремовый фон `#F3EFE6`, светлые карточки `#FAF8F3`, лесной зелёный `#1F3A2D`, шалфейный `#9DAE8C`.
- **Шрифты:** Cormorant Garamond (заголовки) + Manrope (текст) + Caveat (рукописные акценты).
- **Формы:** скругления 16–24 px, кнопки-«таблетки», мягкие тени, тонкие линейные иконки.
- **Настроение:** натуральная «аптечно-ботаническая» эстетика: листья, камни, вода, много воздуха.

## Доступность (удобство для всех)
- У всех кнопок-иконок есть подписи для программ экранного чтения (для незрячих пользователей).
- Сайтом можно пользоваться только клавиатурой: видна рамка фокуса, работают Tab, Enter и Esc.
- Контраст текста достаточный для чтения.
- В мобильном меню и окнах фокус не «убегает» за пределы окна.

## SEO (поисковики)
- У каждой страницы есть свой заголовок и описание.
- Страницы товаров содержат специальную разметку **JSON-LD** (цена в тенге, наличие, рейтинг), чтобы Google и Яндекс могли показывать это прямо в результатах поиска.
- Служебные страницы (корзина, вход, админка) помечены «не индексировать».
