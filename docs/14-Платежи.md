# 14. Платежи

Способы оплаты включаются одной строкой в `deploy/.env`:

```env
PAYMENT_METHODS=kaspi_transfer,cash
```

Покупатель видит на странице оформления только **включённые и полностью настроенные** способы. Что настроено, а чего не хватает, видно в **админке → Настройки → «Готовность к запуску»** и командой `python -m app.cli check`. В рабочем режиме сервер не запустится, если включённому способу не хватает настроек.

| Код | Способ | Что нужно | Статус |
|---|---|---|---|
| `kaspi_transfer` | Перевод на Kaspi владельца | `KASPI_PHONE`, `KASPI_RECEIVER` | работает сразу |
| `cash` | Наличными / картой курьеру | ничего | работает сразу |
| `kaspi_pay` | Kaspi Pay для бизнеса (оплата в приложении, автоматическое подтверждение) | `KASPI_MERCHANT_ID`, `KASPI_API_KEY`, `KASPI_WEBHOOK_SECRET` | готов к подключению |

## Перевод на Kaspi (сейчас)

```env
KASPI_PHONE=+7 700 123 45 67     # номер, привязанный к Kaspi Gold
KASPI_RECEIVER=Наргиз К.          # имя получателя, как его видит покупатель в Kaspi
KASPI_PAY_LINK=                   # (необязательно) ссылка Kaspi Pay / QR для оплаты в один клик
```

1. Покупатель оформляет заказ → видит номер Kaspi, получателя, сумму и комментарий «Заказ №1001».
2. Заказ получает статус оплаты **«Ждёт оплаты»** (виден покупателю в личном кабинете вместе с реквизитами).
3. Деньги пришли → админка → **Заказы** → заказ → **Оплата → Оплачен**.

## Наличными при получении

Включён по умолчанию, настроек не требует. Статус оплаты — «Оплата при получении»; после оплаты отметьте «Оплачен».

## Kaspi Pay для бизнеса (когда будет доступ к API)

Всё, что не зависит от Kaspi, уже готово: создание счёта при заказе, переход покупателя на страницу оплаты, приём уведомления, проверка подписи и суммы, защита от повторных уведомлений, статусы.

1. Подключите магазин к Kaspi Pay и получите в кабинете доступ к API (ID магазина, ключ API, секрет для уведомлений).
2. В `deploy/.env`:

   ```env
   PAYMENT_METHODS=kaspi_transfer,cash,kaspi_pay
   KASPI_MERCHANT_ID=…
   KASPI_API_KEY=…
   KASPI_WEBHOOK_SECRET=…
   ```

3. В кабинете Kaspi укажите адрес уведомлений об оплате: `https://<домен>/api/payments/kaspi/webhook`.
4. Программист сверяет с документацией Kaspi Pay места, помеченные **`KASPI API`** в `backend/app/services/payments/kaspi_pay.py`: адрес создания счёта, названия полей, способ подписи уведомлений.
5. Перезапуск: `docker compose -f deploy/docker-compose.yml up -d backend`. Проверить — тестовый заказ на небольшую сумму.

Как сервер обрабатывает уведомление Kaspi:

- без верной подписи (`X-Signature`, HMAC-SHA256 с `KASPI_WEBHOOK_SECRET`) — отказ, в журнале запись;
- сумма не совпадает с суммой заказа — отказ (заказ не отмечается оплаченным), в журнале ошибка;
- заказ уже оплачен — повторное уведомление ничего не меняет;
- пока `kaspi_pay` выключен, адрес уведомлений не отвечает вовсе.

## Как добавить новый способ (например, оплату картой через платёжный сервис)

Все способы оплаты — в папке `backend/app/services/payments/`:

```
payments/
├─ __init__.py        список способов (METHODS), выбор включённых, проверка готовности
├─ base.py            общий вид способа: code, title, text, env, start(), instructions()
├─ kaspi_transfer.py  перевод на Kaspi
├─ cash.py            при получении
└─ kaspi_pay.py       Kaspi Pay API: счёт, подпись и разбор уведомления
```

1. Скопируйте `kaspi_pay.py` в новый файл (например, `cloudpayments.py`), поменяйте `code`, `title`, `text`, список нужных настроек `env` и запрос создания платежа в `start()`.
2. Добавьте класс в `METHODS` в `payments/__init__.py` и поля настроек в `backend/app/core/config.py`.
3. Если сервис присылает уведомления — добавьте маршрут по образцу `kaspi_webhook` в `backend/app/api/routers/orders.py` (подпись → сумма → повтор).
4. Добавьте код способа в `PAYMENT_METHODS`. Сайт покажет новый способ сам — менять фронтенд не нужно.

Сумму платежа всегда считает сервер по ценам из базы; цену из браузера подменить нельзя (это проверяют тесты).
