# Тесты проекта

Тест — маленькая программа, которая сама проверяет, что сайт ведёт себя правильно: например, «если покупатель подменит цену в запросе, сервер всё равно возьмёт цену из базы». Тесты запускаются одной командой и за минуту проверяют то, что вручную заняло бы часы. В GitHub они запускаются автоматически при каждом изменении.

## Что проверяется и последние результаты

| Набор | Где | Что проверяет | Тестов |
|---|---|---|---|
| Аккаунты и основные функции | `backend/tests/test_api.py` | регистрация, вход, коды из писем, профиль, товары, заказы, отзывы | 12 |
| **Безопасность** | `backend/tests/test_security.py` | SQL-инъекции, XSS, права доступа, перебор паролей и кодов, лимиты, заголовки, загрузка файлов, подпись оплаты, утечка секретов, настройки production | 31 |
| Проверка входных данных | `backend/tests/test_validation_cases.py` | границы и неверные значения во всех формах | 55 |
| Каталог | `backend/tests/test_catalog_cases.py` | категории, адреса товаров, тексты и фото сайта | 11 |
| База данных | `backend/tests/test_database_cases.py` | ограничения, уникальность, связи, каскадное удаление, откат | 25 |
| Сценарии заказов | `backend/tests/test_order_scenarios.py` | оформление, доставка, остатки, отмена, чужие заказы, сбой оплаты | 15 |
| Логика сайта (JS) | `tests/frontend/*.test.cjs` | экранирование, цены, маска телефона, ссылки, корзина, избранное, фильтры каталога | 77 |
| Публикация | `tests/general/test_public_build.py` | в `.public/` попадают только публичные файлы, адрес API проверяется | 38 |
| **Итого** | | | **264** |

Все 264 теста проходят. Сервер проверяется на SQLite (локально) и на PostgreSQL (в GitHub, `.github/workflows/backend.yml`).

Кроме автотестов, сайт проверялся в настоящем браузере (Chrome): все страницы и разделы админки в демо-режиме и с сервером, под гостем, покупателем и администратором, на телефоне и компьютере (276 открытий страниц), сквозные сценарии «регистрация → заказ → оплата → подтверждение администратором» — без ошибок.

## Как запустить

Сервер (из папки `backend`, после `pip install -r requirements-dev.txt`):

```bash
python -m pytest
```

Логика сайта (из корня проекта, нужен Node.js 20+):

```bash
node --test tests/frontend/utils.test.cjs tests/frontend/store.test.cjs tests/frontend/catalog.test.cjs
```

Публикация (из корня проекта):

```bash
python -m pytest
```

## Как устроены

- Тесты сервера работают на временной базе, которая создаётся заново для каждого теста; письма не отправляются — коды перехватываются. Настоящие данные не затрагиваются.
- Тесты JS загружают настоящие файлы сайта в изолированную «песочницу» с поддельным хранилищем браузера.
- Тесты публикации работают во временной папке и не трогают настоящую `.public/`.
- Платёжные сервисы не вызываются — их ответы имитируются.
