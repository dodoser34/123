# Тесты проекта

Проверки необязательной демонстрации находятся в `demo/tests/` и запускаются через `python -m pytest demo/tests -q`. Они проверяют включение всех фото, отсутствие рабочего API, отдельное хранилище и сборку основного сайта без папки демонстрации.

Тест — маленькая программа, которая сама проверяет, что сайт ведёт себя правильно: например, «если покупатель подменит цену в запросе, сервер всё равно возьмёт цену из базы». Тесты запускаются одной командой и за минуту проверяют то, что вручную заняло бы часы. В GitHub они запускаются автоматически при каждом изменении.

| **Итого** | | | **289** |

После отделения демонстрации локально прошли все 289 тестов. Серверный набор выполнен на временной SQLite; проверка PostgreSQL настроена в `.github/workflows/backend.yml`, её новый результат нужно смотреть в GitHub Actions.

Для текущей версии выполнены 24 проверки в Chrome: вход тестового покупателя, добавление/изменение/удаление в корзине и избранном, основные страницы, три ширины экрана, отдельное хранилище и декодирование всех 65 фото. Основная production-сборка также открыта без демо: каталог, вход и доставка загрузились без ошибок JavaScript и запросов к demo/, оформление требует входа. Внешние запросы к шрифтам блокировались в этой изолированной проверке. Полный аудит безопасности ещё не завершён; прохождение тестов не означает отсутствие всех уязвимостей.

## Как запустить

Сервер (из папки `backend`, после `pip install -r requirements-dev.txt`):

```bash
python -m pytest
```

Логика сайта (из корня проекта, нужен Node.js 20+):

```bash
node --test tests/frontend/utils.test.cjs tests/frontend/store.test.cjs tests/frontend/catalog.test.cjs
```

Публикация (из корня проекта):

```bash
python -m pytest
```

## Как устроены

- Тесты сервера работают на временной базе, которая создаётся заново для каждого теста; письма не отправляются — коды перехватываются. Настоящие данные не затрагиваются.
- Тесты JS загружают настоящие файлы сайта в изолированную «песочницу» с поддельным хранилищем браузера.
- Тесты публикации работают во временной папке и не трогают настоящую `.public/`.
- Платёжные сервисы не вызываются — их ответы имитируются.
